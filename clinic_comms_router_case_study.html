The Problem

Every clinic needed outreach to the account teams behind each registered account — a pre-invite nudge, a Teams heads-up, a post-clinic follow-up. That outreach was happening manually: finding the right rep, writing the message, sending it one account at a time. The account and registration data already lived in a tracker I'd built. The messaging didn't talk to it.

What I Built

A communication layer on top of the existing registration tracker. Pick a clinic, choose how to target — a single rep or everyone in a role — and the tool pulls that rep's exact account list into a pre-filled, ready-to-send message. Three message types covered the full cycle: a pre-invite nudge, a Teams chat message, and a post-clinic follow-up, each pulling live from the same underlying account data instead of being written from scratch.

Why Not Just Buy a Platform?

Dedicated internal-comms platforms already exist for this — targeted, dynamic-content mass messaging is a mature software category. That wasn't the point. I wasn't trying to replace that category; I was closing a specific gap in one program's workflow using what we already had, without a new procurement cycle or vendor contract. The value was proving the workflow — target by role, pull the right accounts automatically, send from one place — was worth building before anyone spent money solving it a bigger way.

How It Connects

03

Send — copy to Outlook or post to Teams. I validated with the AI Adoption team that this step could run through existing API triggers rather than manual copy-paste — that connection work was scoped but not completed before ownership moved.

Reading It Honestly

This tool never got wired to a live Teams or Outlook API — it stayed a working prototype with a manual copy-paste handoff at the last step. The team agreed the trigger-based connection was technically feasible, but the work to build it fell outside what our team could take on. I'm showing the workflow it was designed to enable, not a claim that it ran unattended in production.

What This Taught Me

Not every gap needs new software — some need the data you already have connected to the outreach you're already doing. I also learned where my build should stop: scoping a working prototype to prove the workflow, then handing the "connect it to production systems" piece to the team that owns that infrastructure, rather than trying to own a system integration I wasn't positioned to maintain.
