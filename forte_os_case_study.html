The Problem

Raw customer signal — what retakers actually say about failing, what overwhelms them, what competitors get wrong — was scattered across Reddit, Facebook groups, and TikTok with no pipeline connecting it to what Forte actually builds and sends. Manually reading and synthesizing that signal every week doesn't scale, and it's too slow to catch what's happening in real time.

What I Built

A five-layer operating system that runs itself. Each layer hands off to the next automatically, on a schedule, with built-in checks that stop the pipeline rather than publish on bad data.

The Five Layers

01

Capture — automated scrapers pull fresh customer conversation weekly (Reddit, Facebook) and bi-weekly (TikTok), landing raw data in a shared drive with zero manual export.Apify → Google Drive

02

Process — a Python engine filters raw posts into qualifying signal: context-aware keyword rules, promo filtering, freshness gates, and a security scan for injected or malicious content before anything downstream runs.Custom Python pipeline

03

Orchestrate — nine scheduled tasks run the pipeline end-to-end on cron: pull data, process it, rebuild the keyword master, append an append-only strategic memory log, and generate outputs — with week-over-week deltas tracked automatically.Scheduled task orchestration

04

Store — structured signal routes into Airtable as content-intelligence records; a separate Airtable base tracks live customer orders, fed automatically the moment a purchase happens.Airtable + Zapier

05

Distribute — a formatted weekly strategy brief lands as a Google Doc, a live dashboard rebuilds itself with fresh data, and ready-to-send email sequences are drafted from the week's strongest signal.Google Docs + live dashboard

It Catches Its Own Mistakes

The pipeline isn't fire-and-forget. When one data source went quiet for five weeks, I caught the gap, diagnosed it, and ran a one-time backfill task with a widened date window to recover the missing signal — rather than letting the strategy brief silently run on incomplete data. When a filter was over-aggressively dropping relevant posts, I audited it against real data and fixed the logic. That audit trail — every run, every fix, dated — is part of the system, not an afterthought.

Reading It Honestly

This is operational infrastructure I designed, built, and maintain for a real business — not a one-time analysis or a static dashboard. The value isn't any single output; it's that the whole chain from raw signal to distributed strategy runs on its own, catches its own data-quality problems, and gets corrected when something breaks.

What This Taught Me

Building one dashboard is a data project. Making five different systems hand off to each other reliably, on a schedule, without someone watching it — that's an operations problem, and it's a different skill. I learned to design for failure as much as for success: every layer in this pipeline has a check that stops it from doing the wrong thing quietly.
